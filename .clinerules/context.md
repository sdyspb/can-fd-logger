# Память проекта: CONTEXT.md  CONTEXT.md в корне — основной актуальный источник контекста проекта (язык — английский, решение пользователя от 2026-10-11; форма 8 разделов фиксирована, не перестраивать). Дополнения по сессиям: `CONTEXT-<n>.md` (n = номер сессии) — результаты сессии, анализы, дельта статуса.  ## Обязательная структура (разделы в этом порядке) 1. Суть проекта — платформа, стек, сборка, назначение. 2. Сборка / загрузка — команды, окружение, запретные файлы. 3. Карта пинов — таблица «Пин | Назначение» + примечания. 4. Протокол — актуальное состояние — формат пакетов, таблица реализованных    команд, проверенные примеры, механика транспорта. 5. Карта файлов — таблица «Файл | Роль». 6. Известные проблемы — нумерованный список + пометка «НЕ чинить без явной задачи». 7. Открытые задачи — приоритет сверху вниз. 8. Конвенции / правила — как писать код в этом проекте.  ## Правила ведения - Начало сессии: прочитай CONTEXT.md и самое свежее CONTEXT-<n>.md — это   полный ввод, сразу бери задачу. Если файлов нет: создай по этой структуре,   заполнив по коду. - Блок «ИНСТРУКЦИЯ ДЛЯ НОВОЙ СЕССИИ / ИИ-АГЕНТА» в шапке файла не удалять. - После изменений кода сразу обновляй затронутые разделы, не дожидаясь просьбы. - Задача сделана → убрать из раздела 7. Проблема решена → убрать из раздела 6. - CONTEXT.md отражает только текущее состояние, без истории (дополнения —   исключение: они и есть история по сессиям, сохраняются). - После обновления пара (CONTEXT.md + свежее дополнение) должна оставаться   самодостаточной: новой сессии должно хватить, чтобы понять проект и работать. - Дополнения по сессиям (конвенция от 2026-10-11): результат сессии записывается   в `CONTEXT-<n>.md` (n = номер сессии, корень репозитория); CONTEXT.md   обновляется только точечными правками — крупные переписывания опасны   (сессия 13 упала на редактировании CONTEXT.md). - Другие файлы-«памяти» не создавать (допускаются только CONTEXT.md + CONTEXT-<n>.md).
